cosmoai-adept — System Architecture

agent_core is the hub-and-spoke engine every COSMO family agent (Discord bot, CLI tool, scheduled job) is built on top of: one shared library supplying checkpointed memory, sandbox enforcement, human-in-the-loop approval gates, and live WebSocket telemetry, so each entrypoint only has to define what makes it different.

AgentSpec → build_agent()

Every entrypoint (Discord Bot, CLI Tool, or anything future) supplies one AgentSpec — name, system prompt, tools, sandbox root, model backend. build_agent(spec) compiles it into an executable LangGraph ReAct agent. Write the agent-specific bits once; get checkpointed memory, sandboxing, approval gates, and telemetry for free.

Compiled LangGraph ReAct Agent

The runtime graph. Tool calls route through an execute_tools gate; failed tools return a ToolMessage the model can reason about and recover from, never a raw exception that crashes the run.

safe_path() — sandbox wall

Rejects path traversal and symlink escape within a sandbox root that is bound once, at tool-construction time, by whoever builds the AgentSpec — never accepted as a model-supplied argument. _assert_no_model_controlled_sandbox() exists specifically to guard the regression (ADR-009).

approvals.py — human-in-the-loop gate

High-risk actions are gated mechanically, not by prompt instruction. A tool name listed in approval_required pauses for a human decision at the tool-execution layer, the same layer safe_path() lives in.

SQLite Checkpointer — per-agent memory

One database per agent, scoped by thread_id, deliberately kept out of the sandbox root a model's own file tools can reach — a model can't read another thread's history or corrupt its own checkpoint state through write_file.

Pluggable Tool Library

File I/O, logging, web search, weather, TTS, and digest generation — all least-privilege, all declaring exactly the inputs they need, nothing reaching outside its sandbox by default.

events.py — WebSocket broadcaster

Lazy-started: if nothing's listening, it's a no-op — zero cost, zero coupling. Every model and tool call broadcasts a telemetry event when something is.

Model Backend

spec.backend selects "anthropic" (cloud, default) or "local" (any OpenAI-compatible local server, e.g. LM Studio). Only _build_model() branches on this — graph, tools, memory, and telemetry are identical either way.

Live Visualizer (Godot 4)

A 2D top-down scene, fed live over WebSocket, where the agent walks to the station for whichever tool it's calling and shows a speech bubble with what it's doing — the same telemetry a production on-call dashboard would show, just legible at a glance instead of buried in logs.
